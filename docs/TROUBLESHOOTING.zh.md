# 排障

[English](TROUBLESHOOTING.md) | 简体中文

## 插件看起来没挂上

- preset 的行**永远不会**出现在 `dsh --profile web --dump-config` 里，因为 preset 是在会话启动时组合的，不在 profile 合成树里。它不在那儿不能说明任何问题。
- 行的解析基准是**正在启动的那个 profile**，不是 `DSH_HOME`。只装进 web profile 的插件，在 headless 启动时解析不到。
- 如果行里的包解析不到，整个 preset 会被报成 broken 并且不被使用（而且是静默的），所以先确认引擎可达，再去查别的东西。

## 熔断从不跳闸

- 熔断只统计**自动**压缩。手动压缩会重新武装它，比阈值更长的健康间隔也会。
- 触发条件是**回填太快**，不是上下文很大。一个压一次就稳住下来的会话永远不会触发它，这是设计如此。
- 如果该会话的自动压缩已经关掉了，那就根本没有东西去调那个门控，也就没有什么可跳闸的。

## 压缩停了，却没人说为什么

- 从自动路径抛出的错误会被宿主记录并吞掉，所以可见的信号是那段 prompt 与那行 warn，而不是一个失败。
- 去找那行 warn，它写明连续次数、阈值与上一次间隔。
- 跑 `/compaction-breaker` 看熔断是否处于锁定状态，再用 `/compaction-breaker reset` 重新武装。

## 不开浏览器怎么查看

- 用 `--patch` 挂一个探针插件并让它写文件；CLI 启动不产出 logger 流，所以打日志算不上证据。
- 不开会话也能组合出 preset 域：依次调 `agents.create` 与 `agentPresets.mount`，这正是生产环境的会话控制器所做的两次调用。
- 把引擎从域里读回来，确认到底是哪个类在服务 `ctx.compaction`，以及它解析出了什么策略。
